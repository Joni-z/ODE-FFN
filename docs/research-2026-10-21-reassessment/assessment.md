# ODE-FFN：先把研究问题重新立住

这次复盘后的判断是：**现在缺的不是更多配置，而是解释“原版 ODELayer 的哪一条结构限制，为什么有利于学习我们的目标函数”。** 前几轮完成了不少有价值的排除，但我把“还能做一个合理消融”推进得太快，没有及时把证据收束成明确的问题。上一轮建议的窄 SiLU 对照也先不跑。

我重读了谱约束、阶数、门控来源、预算对照、冻结 checkpoint 换阶数、求解器分辨率和最新门控实验；核对了 synthetic 与当前 JiT 的实现，并检查了相关原始论文。完整推导放在 [mathematics.md](mathematics.md)，逐项证据在 [evidence.md](evidence.md)，论文及阅读范围在 [literature.md](literature.md)。本轮只做了确定性数学核验，没有新训练，也没有改提交过的 Report 1。

## 1. 先放下两个没有站住的出发点

第一个是“FM 是连续流，所以 FFN 越像精确 ODE 就越好”。它有直觉吸引力，但缺少中间的逻辑。

原版 K2 是：

```text
out = h + s(h)*P*h + s(h)^2/2*P^2*h
```

这里 s 从当前输入算一次，之后不更新。它逼近的是“把这个 s 冻住的线性系统”。如果真把隐藏动力学定义成 `dh/du=s(h)*P*h`，二阶展开还会多出一项与 `grad(s)` 有关的量。更何况外部 FM 的二阶展开涉及整个速度网络的时间导数和 Jacobian，不能用隐藏层的 P² 代替。

实验也没有支持“指数越准越好”：把训练好的低阶层改成精确指数，六个 K1/K2 对照全部变差；Ring8 K2 的 oracle 误差也从 0.0287 升到 0.1694。这说明网络适应了原来的多项式。它不说明从头训练精确指数一定不好，但已经足以停止把“修正截断误差”当作默认研究主线。

第二个是“P 的谱越小、越平均，模型越适配 FM”。已有 cap 确实压小了内部敏感性，却没有一致改善生成。我们也从未真正测试过奇异值均匀化，cap 只是整体缩放。

**约束的目的必须先确定。** 是防止非有限训练？控制某种误差传播？还是改善优化条件？这三件事需要的数学条件并不一样。现有训练没有给出“普遍发散需要修复”的证据。

## 2. 原版到底有什么值得研究的结构

先看 s 不随输入变的情况。整个 ODEFFN 可以严格写成：

```text
out = B2 * SiLU(B1*h)
Bi = I + si*Pi + si^2/2*Pi^2
```

所以它是一种普通 FFN 的矩阵参数化。学习一个常数 s 也没有增加函数类，因为可以把 s 吸收到 P。这解释了最新实验里 fixed 和 scalar 几乎重合。

真正额外的东西在于输入相关的 s：不同输入使用不同的有效矩阵，但它们不是任意变化，而是沿着由同一个 P 决定的一条曲线变化。K2 的一阶和二阶系数还被 `s²/2` 绑定。**这里值得研究的是“受限制的、随输入变化的线性变换”，而不是 ODE 这个名字。**

这个限制是否有价值，当前仍不知道。它可能用较少自由度组织出有用的变化，也可能是不必要的束缚。门控能带来非线性不等于这种特定的绑定方式值得保留；K1 本身也已经是一个输入门控残差层。

另外，矩阵多项式会改变参数的优化几何。我推导出 K2 对矩阵扰动 H 的响应是 `H+(AH+HA)/2`，其中 A=sP。它会放大某些参数方向、压小另一些方向，甚至在 A=-I 处所有一阶变化都消失。因此即使固定门控有收益，也可能来自优化路径，而不是流的表达能力。这是第二条可研究的解释，尚不是已经验证的优点。

## 3. 从 objective 出发，能找到什么更具体的数学目标

在我们目前的独立高斯噪声、线性插值设置下，最优速度是条件平均：给定当前位置和时间，把所有可能的起点终点配对对应的速度平均起来。

进一步推导后，它的空间导数可以严格拆成：

```text
最优速度的 Jacobian
  = 一个各方向相同的收缩项
    + 一个由“给定当前位置后，干净终点还有多少不确定性”决定的半正定项
```

后面这一项就是条件协方差乘以时间系数。这类恒等式已有理论基础，不能算我们的新定理；但把它落实到现有实验，能给研究一个准确的对象。[相关理论](https://arxiv.org/html/2604.06065v1)，[denoiser 导数与条件协方差的联系](https://arxiv.org/html/2502.02150v3)。

我们已有的数据已经能展示这个问题，不需要再编一批数据：

- **Gaussian：**在 t=0.5，一条方向的真实导数是 -1.67，另一条是 +1.20。目标本来就需要一边收缩、一边扩张。
- **Ring8：**在同一时刻，相邻簇之间的一个中点上，两条方向的导数约为 -1.72 和 +3.34。到了 t=0.8，簇中心可以两方向都收缩，簇间仍可能有很强的分离方向。

这些是由现有分布参数算出的解析结果，与仓库 oracle 和自动微分核对一致。它们不是训练结果；低密度区域的巨大导数也不能直接当作平均误差的主因。

这给出一个比“让谱更稳定”更具体的问题：**模型能否在需要的时间、位置和方向上产生适当的收缩与扩张？原版的输入门控是否在帮助完成这件事？**

## 4. 现有结果给这条问题提供了线索，但还没有完成归因

最新 Ring8 实验里，取消输入门控之后，oracle MSE 从 0.0325 变为约 0.0746，簇间杂点也明显增多。这个信号值得解释。同时，SwiGLU 的 oracle MSE 是 0.0162，簇间杂点还更少。因此不能说原版已经找到了更优结构。

数学上，单个 ODELayer 的输入门控给 Jacobian 增加一个 rank-one 项；两个层组合后，相对冻结门控的局部导数，修正的秩至多为二。Ring8 在两个候选簇之间的条件协方差也可以近似是 rank one。这提供了一个具体猜想：门控可能在需要区分候选模式的位置，提供了方向性的修正。

**但两个 rank one 不是同一个东西。** 一个在隐藏空间，一个在数据空间；隐藏项还未必对称、未必指向正确方向。我们目前保存的主要是范数和时间分段均值，无法证明它们对齐。输入门控组还多了约 2.5 万参数，这是另一种解释。

所以现在适合写下来的假设是：

> 原版 ODELayer 的价值，如果存在，可能来自共享 P 的多项式与输入门控共同形成的方向性适配；这种适配应当减少目标场在模式分离区域的特定误差，而不只是让某个全局范数变小。

这里的“如果存在”很重要。我们还没有证据把它升级成论文结论。

## 5. 我建议的优先级

| 优先级 | 要回答的问题 | 为什么值得考虑 | 什么情况下应停止这条解释 |
|---|---|---|---|
| 第一：解释输入门控 | 门控经过整个网络以后，是否改善了模式不确定区域的方向性场误差？ | Ring8 的 gate 消融有信号；目标场有解析表达式；现有 checkpoint 可以用于验证 | 若改善不集中在预期区域/方向，或通用门控同样解释全部收益，就不再声称 FM 特有适配 |
| 第二：解释多项式参数化 | 共享 P 和固定系数是否改善优化，还是带来冗余和困难？ | 常数门控的等价式、K1/K2 的参数化差别、冻结换阶数结果都指向这个问题 | 若合适的普通 FFN 对照已解释结果，就不把它包装成连续流优势 |
| 暂缓：设计 P 约束 | 是否存在某种“超过目标需求的放大”，确实造成可测误差？ | 只有先找到失败机制，才知道应约束什么 | 没有超额放大证据，或者约束同时压掉所需方向，就不继续扫 cap/谱形状 |

第一步应当是整理现有 checkpoint 的解释方案：在相同输入和时间上，对照解析目标的方向、模型的方向、以及门控经过外部层之后的贡献。必须区分训练插值点和生成轨迹点，也必须记录区域概率。有限差分或小幅局部干预可以检查方向预测，不能把大幅关门控后的分布漂移直接当作精确归因。这是待确定的诊断计划，不是本轮又放出去的实验。

等机制能说清，再决定是否需要一个最小的训练对照。窄 SiLU、解耦系数、结构化 P 都只是可能的区分工具，现在不选一个先跑。每次未来训练都应该提前写清：它区分哪两种解释，以及两种结果分别意味着什么。

## 6. 回到 JiT 之前，还有一个必须修复的解释断层

JiT 预测的是干净图像，再通过 `(D(x,t)-x)/(1-t)` 一类转换得到速度；toy 直接输出速度。这种参数化差别影响有限容量网络应该把能力用在哪里。[JiT 的原论文](https://arxiv.org/html/2511.13720v2)对此有直接实验。

代码还有一个更具体的区别：当前 image registry 中 `ode` 指向带 RMS 归一化的单层 ODEOnlyFFN，而 synthetic 用的是教授的双层原版。因此历史 `ode` 的 FID 不能直接给当前研究背书。历史 checkpoint 的源码和配置需要恢复后逐项确认；本轮 torch 认证失败，不能声称已经重查全部老图像日志。

如果后续获得清楚机制，再把问题翻译成“这种 hidden block 为什么有利于条件去噪”，才是迁移回 JiT 的合理入口。现在直接回去跑更大的图像任务，只会放大解释难度。

## 7. 哪些文章现在真正值得读

先读 **JiT 的目标参数化**、**2026 年 Lipschitz regularity 的条件协方差推导**、**Preconditioned Flow Matching 的 Gaussian 优化分析**。前者明确最终要服务的模型，后两者分别明确目标场和优化问题。后两篇是预印本，不能把所有结论不加条件地搬过来。

随后用 **Mamba** 检查“输入相关步长”的已有工作，用 **MeanFlow** 看“先定义目标量，再从恒等式推训练设计”的研究方式。读它们不是为了把项目改成 Mamba 或 MeanFlow。完整链接、指定章节、局限和实际阅读范围见 [精选文献](literature.md)。

我们已经得到的是一组有用的排除和一条可检验的机制线索。下一阶段应把“受限制的输入相关算子是否适合条件去噪/速度场的局部几何”讲清楚；如果证据不支持，就收缩结论，而不是不断增加新 block 来维持最初的设想。
