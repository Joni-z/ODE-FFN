The goal is to retain the original idea of approximating a conditional linear

The existing ISRU-D K1 result motivates the diagonal choice; it is not a K8
result. Image performance and K8 exponential-action accuracy remain to be measured.

## Exact operator

For each token of width d, independently, define a single internal layer:

```text
d0 = rsqrt(1 + 1.2 * h0^2)          # elementwise; computed once at entrance
A0 = P diag(d0)
T8(h0; P) = sum_{k=0..8} A0^k h0 / k!

# Matrix-free evaluation of the same polynomial:
term = h0
out = h0
for k in 1..8:
    term = P(term * d0) / k
    out = out + term

# Complete FFN:
a = T8(h; P1)
b = SiLU(a)
FFN(h) = T8(b; P2)
```

Each layer approximates exp(A0)h0, the solution at internal time one of
dy/dr = A0 y. D0 is held constant across that layer's eight Taylor terms, but
remains differentiable with respect to its entrance input. The second layer
computes its own D from b. Do not recompute D from each intermediate term,
apply q to each term, or replace the polynomial by eight Euler substeps.

P1 and P2 are separate, bias-free d-by-d matrices, each reused eight times.
Keep the existing
Linear/Kaiming-uniform initialization distribution; do not zero-initialize
both matrices or introduce extra projection, normalization or trainable rate
parameters. The input and output shapes are identical. The complete JiT block
retains the author's pre-normalization, conditioning and outer residual gate:

```text
z = modulate(RMSNorm(x), shift(t, c), scale(t, c))
x = x + gate(t, c) * FFN(z)
```

Here c is absent/dropped for unconditional training. Attention and the rest of
the author's block remain unchanged. The FFN receives the already conditioned
features; it does not introduce a second global-time controller.

The inherited parameterization comes from the
[cycle13 builder](../../studies/muon_pd_20261102/autoresearch_20261103/cycle13/trial13.py)
which replaces the input diagonal in two K1 maps around SiLU. Its inherited
[forward](../../studies/muon_pd_20261102/reference/synthetic/models.py)
applies the diagonal before P. The selected K8 extends that polynomial order;
it is now implemented in the active image hook. K1/K8 reductions, an independent
dense polynomial, derivatives and matrix exponentiation pass the documented
small-fixture checks before queued GPU validation.

## Why choose it

At K1, D(h)h equals q(h) = h/sqrt(1 + 1.2h^2), the ISRU response and the exact
scalar solution of dy/dr = -y^3 at r = 0.6. At K8, the object approximated is
the conditional linear flow generated by A0 = P D(h0). These are distinct
interpretations. D scales the entrance coordinates, while repeated application
of the same A0 supplies the original Taylor/exponential structure. The full
FFN is not guaranteed to be contractive, and finite K8 is not an exact solve.

The engineering hypothesis is that this shared-generator polynomial can turn
additional computation without additional P parameters into useful image
modeling. Test this directly rather than asserting image benefits from synthetic
MSE. Ring8 gives MSE 0.009773 versus selected Swi64's 0.011279; sampling nearly
ties, and Product16 favors ordinary controls. These results motivate a trial,
not a guarantee. See the [complete comparison](../autoresearch/professor-20261103/cycle14-results-complete/analysis-report.md).

Retain coefficient 1.2 and the existing SiLU placement. K1 remains an order
control, not the selected main candidate. Keep Muon, adaptive frames and
additional spectral penalties out of the first structural comparison; the
current optimizer recommendation remains the same AdamW recipe across arms.

## Capacity and minimum comparisons

At fixed model width d, both K1 and K8 have 2d^2 matrix weights. K8 performs
sixteen d-by-d matrix-vector products per token across the two layers, for
16d^2 forward dense MACs. Native JiT's ratio-4 SwiGLU uses approximately 8d^2
weights and MACs. Thus K8 has roughly one quarter of its FFN matrix parameters
but twice its FFN forward dense MACs. The earlier quarter-compute statement
applies only to K1. These are not whole-model training FLOPs or wall times.

For d = 768, ignoring biases and pointwise operations:

| FFN | Matrix weights | Forward dense MACs per token | Purpose |
|---|---:|---:|---|
| Native SwiGLU, intermediate width 2048 | 4,718,592 | 4,718,592 | Author architecture and practical reference |
| ISRU-D K8, two 768-by-768 maps | 1,179,648 | 9,437,184 | User-selected candidate |
| ISRU-D K1, same two matrices | 1,179,648 | 1,179,648 | Order control at equal parameters |
| SwiGLU, intermediate width 512 | 1,179,648 | 1,179,648 | Ordinary parameter-matched control |
| SwiGLU, intermediate width 4096 | 9,437,184 | 9,437,184 | Optional FFN forward-MAC-matched control |

Retain the original SwiGLU equation when changing intermediate width. The
smaller SwiGLU is no longer compute-matched to K8; parameter and compute
controls answer different questions. Do not infer a speedup from fewer
weights. The final ordinary-control budget and launch grid remain to be
registered after throughput measurement. Free ISRU remains an attribution
control with separately recorded initialization and residual placement.
